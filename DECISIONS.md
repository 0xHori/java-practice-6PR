# Архитектурные решения (DECISIONS.md)

## Решение 1: Приоритет правил через early return

**Проблема.** Правила пересекаются: ПДн, HIGH-риск, лимит, срочность. Вложенные `if-else` дают неоднозначный приоритет.

**Решение.** В `ApprovalRouter.route()` — плоский список `if` с `return` от строгого к общему: ПДн → HIGH → лимит → urgent → STANDARD. Первое сработавшее правило завершает метод.

**Следствие.** Порядок `if` фиксирует приоритет. Срочная заявка с ПДн не может уйти в FAST_TRACK.

## Решение 2: Порог лимита в одной константе

**Проблема.** Вариант 1 меняет лимит на 550 000. Дублирование числа по классам ломает изменение.

**Решение.** `ApprovalRouter.FINANCE_LIMIT = 550_000L` — единственное место с порогом. `isFinanceReviewRequired(amount)` читает только его. Конструктор `ApprovalRouter(long)` позволяет переопределить лимит без правки класса.

**Следствие.** Изменение порога на защите — одна строка в одном классе.
